Hay aplicaciones de laundry, hábitos de organización open source

Existen excelentes herramientas de código abierto enfocadas en hábitos, organización de tareas del hogar y gestión del día a día, aunque casi no existen proyectos open source dedicados con exclusividad matemática a lavar ropa.

La solución habitual en la comunidad open source es utilizar gestores de tareas domésticas recurrentes o trackers de hábitos altamente configurables:

Organización de tareas del hogar y mantenimiento

Grocy: El ERP definitivo para el hogar, self-hosted y de código abierto. Maneja inventario de despensa, compras, pero destaca en su módulo de tareas domésticas (chores): permite fijar frecuencias flexibles (ej. "lavar sábanas cada 14 días" o "lavar ropa oscura al llegar a X carga"), asignar responsables y llevar registro histórico.

Vikunja: Un gestor de tareas (to-do) potente, visual (tableros Kanban, listas, diagramas de Gantt) y con soporte completo para recurrencias complejas (ej. "repetir 3 días después de completada la última vez"), ideal para rutinas cíclicas de limpieza y lavandería.

Hábitos y rutinas recurrentes (Móvil / Android)

Loop Habit Tracker: Disponible en F-Droid y GitHub. Es minimalista, sin anuncios, totalmente offline y centrado en la consistencia. Permite crear hábitos con repeticiones personalizadas (por ejemplo: 2 veces por semana, cada domingo, etc.) y ofrece gráficos limpios de rachas y frecuencia.

Habitica: Combina el seguimiento de hábitos y listas de tareas con un formato RPG / gamificación. Su base de código es abierta y permite configurar rutinas diarias o semanales (como días de colada) donde ganas experiencia o pierdes puntos de vida si las descuidas.

Table Habit / Everyday Habit Tracker forks: Clones y proyectos libres en GitHub pensados para llevar un registro visual en cuadrícula de tareas de autocuidado y orden doméstico.

Organización de guardarropa e inventario (Wardrobe management)

Si buscas controlar qué prendas tienes, cómo combinarlas o llevar la cuenta de cuántas puestas tiene una prenda antes de necesitar lavado, proyectos de gestión de activos o armarios virtuales abiertos como WannaWear o catálogos locales en Obsidian (usando plugins como Dataview) se adaptan muy bien a este flujo.

¿Buscas una aplicación móvil directa (estilo APK/F-Droid) para marcar hábitos, o prefieres una plataforma self-hosted en servidor local para gestionar toda la casa?

Quiero que pueda ser configurable o editable personabizalbe con código pero que mantenga lo más posible de esas apps es más que todo adaptarlo a mi mente TDAH, y a mis inspiraciones de como quisiera comportarme

Para una mente con TDAH, el software rígido suele fracasar porque impone una fricción cognitiva que paraliza o cansa rápido. Necesitas visibilidad inmediata, baja fricción de entrada, dopamina rápida y código modificable para ajustar las reglas según cambie tu hiperfoco o tu rutina.

Las mejores alternativas de código abierto que puedes intervenir directamente para adaptarlas a tu lógica interna son:

1. Habitica (Fork propio / API + Scripts)

Base técnica: Node.js, Express, Vue.js y MongoDB (todo en GitHub).

Por qué funciona con TDAH: Transforma tareas aburridas (lavar ropa, tender, doblar) en batallas contra monstruos, experiencia y recompensas inmediatas.

Nivel de personalización: No necesitas montar todo el servidor si no quieres; su API REST pública te permite escribir scripts propios (Python, Node o Cloud Functions) para automatizar reglas: por ejemplo, si dejas la ropa en la lavadora más de 4 horas, un script puede restarte vida o activar un recordatorio más agresivo.

2. Grocy (Webhooks + Custom CSS / Modding)

Base técnica: PHP y SQLite/MySQL, con una API REST exhaustiva y webhooks.

Por qué funciona con TDAH: Elimina la carga mental de recordar cuándo fue la última vez que lavaste sábanas o toallas mediante la lógica de "intervalos dinámicos" (la tarea se agenda X días después de que realmente la hiciste, no en un día fijo que te genere culpa si lo pospones).

Nivel de personalización: Altamente moldeable. Puedes crear una interfaz mínima tipo PWA que solo consulte la API de Grocy y muestre únicamente la "próxima acción inmediata" para no abrumarte con pantallas densas.

3. Obsidian + Dataview + Tracker (Entorno local en Markdown)

Base técnica: JavaScript/TypeScript (mediante Obsidian API y plugins de la comunidad).

Por qué funciona con TDAH: Flexibilidad total sin estructura impuesta. Tus hábitos y el estado de la ropa viven en notas de texto plano.

Nivel de personalización:

DataviewJS: Puedes escribir código JS dentro de tus notas para renderizar paneles dinámicos: botones de un clic para registrar "puse la lavadora", barras de progreso visuales de uso de ropa, o vistas estilo Kanban que solo muestran lo relevante de hoy.

No hay pantallas predeterminadas que te distraigan; diseñas exactamente el dashboard visual que tu cabeza necesita ver hoy.

4. Crear una PWA mínima a medida (Tailwind + Firebase / PocketBase)

Base técnica: Vite + React/Svelte/Vue con un backend ligero como PocketBase o Firebase.

Por qué funciona con TDAH: La mayoría de apps fallan porque tienen 5 clics de más. Si programas tu propia micro-app centrada en un modelo de estados de lavandería (ej. Cesto lleno -> Lavando -> Tendida -> Por doblar -> Guardada), el flujo responde exactamente a tu secuencia mental sin ruido externo.

Actúa como un Coach de Funciones Ejecutivas especializado en Gestión Operativa del Hogar y Cuidado Textil. Tu enfoque se basa en el libro Laundry Love (Patric Richardson): la lavandería no es una tarea pesada, sino un acto de amor propio y cuidado de los activos personales (la ropa). La misión es eliminar la parálisis por análisis, simplificar la toma de decisiones y acompañar al usuario hasta lograr un closet en "Nivel Top".

​Fases de Operación:

​Fase 0: Sincronización y Tiempo (Time-Check)

​Pregunta obligatoria inicial: "¿Qué hora es y cuánta energía tienes (1-10)?".

​Noche (>7 PM): Advertir sobre la falta de sol. Recomendar remojo nocturno solo para algodones/toallas similares, máximo 2 cucharadas de jabón, y sugerir alarma matutina. Advertir no hacerlo con camisas formales o de consultoría.

​Tarde (1–4 PM): Advertir sobre el riesgo de humedad nocturna si las prendas no alcanzan a secar a tiempo.

​Mañana: Luz verde para iniciar el ritual completo.

​Fase 1: Activación de Hiperfoco (El Ritual)

​Audio: Preguntar: "¿Tienes tus audífonos o la bocina lista? ¿Qué vas a escuchar para entrar en la zona?". No avanzar hasta confirmar el anclaje auditivo.

​Hidratación: Sugerir tener a mano agua o café.

​Meta-comunicación: Recordar desconectar del trabajo intelectual/consultoría ("solo somos tú, la música y las fibras").

​Fase 2: Clasificación por Uso y Fibra (Sin Estrés de Colores)

​Reducir la separación a 3 unidades lógicas:

​Soft & Personal (Algodones/Linos): Camisetas, ropa interior, ropa de casa (agua fría, 2 cdas. de detergente).

​Performance & Tech (Sintéticos/Deporte): Ropa elástica/técnica (advertencia: cero suavizante para proteger la transpirabilidad).

​Armor & Home (Pesados): Jeans, toallas, sábanas.

​Fase 3: Tratamiento "Nivel Top" (Patric Richardson Style)

​Triaje de Manchas: Identificar manchas de comida, sudor o café antes de lavar y tratarlas localmente (jabón de barra o vinagre).

​Regla de Oro: Solo 2 cucharadas de detergente; el exceso satura la fibra y ensucia.

​Fase 4: Gestión del Sol y el Viento

​Protección: Colgar prendas del revés para cuidar el color frente a los rayos UV.

​Punto de Humedad Cero: Retirar la ropa en cuanto seque ("si se tuesta, la fibra sufre").

​Sacudida Técnica: 2 sacudidas enérgicas al descolgar para eliminar polvo y relajar las fibras.

​Fase 5: El Cierre (Doblado Vertical y Closet)

​Despejar superficies por completo antes de dar por cerrada la sesión.

​Doblado Vertical: Guiar el doblado tipo archivo (las prendas deben sostenerse en pie).

​Organización: Separar en el closet por contexto de uso (Trabajo/Consultoría vs. Casa/Deporte).

​Inspección final: Apartar prendas con roturas o botones faltantes; no entran al closet hasta repararse.

​Reglas de Interacción:

​Entregar una sola instrucción clara a la vez para no sobrecargar cognitivamente.

​Cerrar cada intervención con: "¿Listo para el siguiente paso?" o "¿Cómo va ese hiperfoco?".

Vamos a cuidar de tus prendas y a despejar la mente paso a paso, sin prisa ni sobrecarga.

Te di el promt algo así necesito en la app

Para traducir la lógica de Patric (Laundry Love) a una aplicación open source y personalizable con código que funcione para una mente con TDAH, la clave es eliminar la vista de lista/calendario tradicional y convertirla en un motor de estados lineales paso a paso (un asistente estilo wizard o máquina de estados finitos).

1. El modelo de arquitectura ideal
En lugar de crear tareas estáticas que se acumulan y causan culpa, la app debe funcionar como una Máquina de Estados:

[ Estado 0: Time-Check ] 
       ↓ (Evalúa hora + energía)
[ Estado 1: Anclaje ] (Check de audio + hidratación)
       ↓
[ Estado 2: Clasificación ] (Solo 3 botones grandes: Soft, Tech, Armor)
       ↓
[ Estado 3: Lavado ] (Temporizador visual + recordatorio de 2 cdas)
       ↓
[ Estado 4: Sol / Secado ] (Regla de humedad cero + sacudida)
       ↓
[ Estado 5: Cierre ] (Doblado vertical + despeje de superficie)
Principios TDAH aplicados al código:

Una sola pantalla a la vez: Nunca mostrar el paso de doblar mientras estás en el paso de clasificación.

Cero parálisis por análisis: La clasificación no te pide separar 6 colores; solo ofrece 3 tarjetas visuales (Soft & Personal, Performance & Tech, Armor & Home).

Alertas condicionales automáticas: Si hora >= 19:00, la app bloquea automáticamente el lavado completo y solo ofrece la rama de Remojo Nocturno.

2. Dos opciones open source para implementarlo
Opción A: PWA Ultraligera a Medida (Recomendada)
Crear una Progressive Web App (PWA) mínima (instalable en tu móvil con un clic) usando Vite + React o Svelte + Tailwind CSS y backend en Firebase o almacenamiento local (localStorage).

Por qué es la mejor opción: Es 100% tuya, sin pantallas sobrantes, sin menús confusos y puedes hardcodear exactamente los textos de Patric.

Componentes clave:

Un componente ActiveSession que solo renderiza el paso actual.

Un botón de avance grande tipo "Listo para el siguiente paso".

Integración con la Web Audio API o temporizadores del navegador para las alertas de fin de ciclo.

Opción B: Front-end personalizado sobre Grocy o Vikunja
Si quieres mantener inventario o historial general:

Utilizas el backend de Grocy únicamente como base de datos (mediante su API REST).

Creas una interfaz web simple (o un script en Node.js/Python) que lea las tareas de lavandería de Grocy pero te las presente con la secuencia de Patric paso a paso, sin que tengas que ver la interfaz densa de Grocy.

Dado que buscas código personalizable y adaptado a tu lógica interna, la solución técnica más limpia no es intentar modificar un monstruo como Grocy, sino armar una Progressive Web App (PWA) de una sola pantalla:

Frontend: Un archivo HTML + Tailwind (CDN) + Vanilla JS o React/Svelte.

Persistencia: Guarda el estado en localStorage (o Firebase) por si cambias de app en el teléfono mientras se lava la ropa.

Que es Tody app

Tody es una de las aplicaciones de limpieza y gestión del hogar más populares, especialmente conocida en comunidades con TDAH porque rompe por completo el formato tradicional de las listas de tareas pendientes (to-do lists).

En lugar de fechas límite fijas o alarmas que generan culpa cuando se acumulan, Tody organiza la casa a través de zonas e indicadores visuales de suciedad/mantenimiento.

¿Cómo funciona?
Organización por áreas: Divides tu casa por espacios (ej. Cocina, Baño, Clóset, Lavandería).

Tareas con intervalos relativos: Defines tareas con frecuencias flexibles (ej. Lavar sábanas cada 14 días, Limpiar filtro de lavadora cada 30 días).

Barras de estado visuales: Cada tarea tiene una barra de color que se va degradando de verde (limpio/reciente) a naranja y rojo (necesita atención). Ves el nivel de urgencia de un vistazo sin leer calendarios.

"Dusty" (Gamificación leve): En la versión de pago o planes avanzados, puedes competir contra un personaje animado que personifica la suciedad/desorden.

Lo bueno y lo limitante frente a tu prompt de Patric
Por qué gusta mucho con TDAH:

Sin culpa por atraso: Si tocaba lavar sábanas el sábado y lo haces el martes, el contador de 14 días simplemente se reinicia a partir del martes. No arrastras notificaciones de "tarea vencida".

Priorización visual: Te dice exactamente qué zona o tarea está en rojo para no tener que decidir por dónde empezar.

Por qué se queda corta para tu caso:

Es de código cerrado y de pago: No puedes modificar su código, ni conectarte a una API abierta, ni cambiar su lógica interna.

No tiene guiado paso a paso (wizard): Te muestra qué toca hacer, pero no te lleva de la mano a través de las fases (Time-check, música, separación de 3 fibras, sacudida, doblado).

Cero lógica condicional: No sabe qué hora es ni cuánta energía tienes para decirte: "son las 8 PM, solo haz remojo nocturno".

Es una excelente herramienta para saber cuándo le toca atención a cada rincón de la casa, pero no actúa como un coach interactivo de ejecución paso a paso.

Hay apps así open source que yo podría adaptar en una pwa?

Sí, existen proyectos open source en GitHub con esa misma filosofía de intervalos flexibles y gestión de tareas del hogar que puedes tomar como base o conectar con una PWA:

1. Donetick (donetick/donetick)
Stack: React en el frontend, Go en el backend, Docker y REST API completa.

Por qué encaja con TDAH: Está pensado específicamente para tareas del hogar (chores), subtareas con reinicio automático y seguimiento por recurrencia flexible.

Cómo adaptarlo a PWA: Tiene una API REST lista para usar. Puedes usar Donetick como tu backend autoalojado y montar tu propio frontend PWA en React/Svelte que consuma esa API para mostrar solo la tarjeta activa de Patric.

2. Grocy (Módulo de Chores)
Stack: PHP / SQLite con API REST exhaustiva y webhooks.

El equivalente open source más directo a Tody: Permite programar tareas con la lógica exacta de Tody: "hacer cada X días después de completada la última vez", sin generar fechas de vencimiento rígidas ni culpa.

Cómo adaptarlo: La interfaz web de Grocy es densa, pero al tener API pública, tu PWA puede simplemente hacer POST /api/chores/{id}/execute al terminar el ritual de doblado.

La paradoja para una mente con TDAH: Adaptar vs. Crear
Hacer un fork de Donetick o Grocy para rediseñarles la interfaz implica lidiar con configuraciones de backend, dependencias de Docker y bases de datos relacionales completas.

Para tu caso específico (donde necesitas cero fricción cognitiva, lógica horaria y acompañamiento paso a paso), suele ser mucho más efectivo montar una PWA "Local-First" (React o Svelte + Tailwind + localStorage):

Estructura tipo Tody: Un tablero visual de tarjetas por frecuencia (Ropa blanca, Ropa de deporte, Sábanas).

Disparador Patric: Al tocar una tarjeta que está "en amarillo o rojo", no te pide marcarla como hecha; en su lugar, despliega el modo ritual Patric (Time-check, música, separación de 3 fibras, sacudida, doblado).

Persistencia sin servidores: Guarda el timestamp de la última lavada en el propio navegador de tu teléfono.
